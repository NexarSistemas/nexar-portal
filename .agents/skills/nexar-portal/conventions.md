# Convenciones

- Revisar arquitectura y estilo existentes antes de introducir patrones.
- Mantener cambios pequeños y focalizados; no hacer refactors no relacionados.
- Usar `snake_case` para SQL y objetos de base de datos.
- Mantener el esquema de nombres y orden existente de migraciones y validaciones.
- Escribir Markdown claro, enlazado y sin duplicar la fuente detallada.
- Usar una rama por cambio, PR obligatoria y Squash and Merge por defecto.
- Escribir commits en español con prefijos como `feat:`, `fix:`, `docs:`,
  `chore:` o `test:` según corresponda.
- Ejecutar tests y validaciones antes del merge. No crear tags ni releases sin
  autorización explícita.

No inventar convenciones de React, Vue u otro framework mientras el repositorio
no demuestre un stack frontend definido.
